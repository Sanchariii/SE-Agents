1. End-to-end request flow

Every node runs through stage_node (stop/lease check, recovery events). A stopped run restores the pre-run snapshot, which includes the brief and the deck design.

Priority in every planner, writer and designer prompt: hard rules > the user's instructions > the planner's directions > the design principles. In collect, components fit their own text, the gate checks rules 1-14 (overlap, overflow, empty or repeated text, repeated or distorted images) plus a clutter advisory, and a passing slide with advisories gets one keep-best polish pass.

2. Questionnaire lifecycle (asked once per session; the size again for a new deck or resize)

The deck size (number_of_slides) is asked for the first deck, and again in the same session only when triage tags a request size_intent new_deck (a new or recreated deck) or resize (the whole deck longer or shorter) and no size is named. reset_size forgets the old size and keeps the request in pending_request; the answering turn plans it. A resize asks only the size. Slide edits, adds, removals and plan feedback never ask it.

6. Max mode: render-and-review for HIGH slides

Consistency: "slide N is inconsistent" redraws that slide (a HIGH slide in a HIGH deck stays on the High Creativity master and matches its neighbours' renders; the odd HIGH slide in a MED deck drops to MED). "The deck is inconsistent" sets the deck to MED, clears HIGH overrides and redraws every slide.
